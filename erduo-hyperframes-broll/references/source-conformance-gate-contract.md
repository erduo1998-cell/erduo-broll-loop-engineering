# Source conformance gate contract

`source-conformance-gate` runs per block from a sealed production contract.
Its receipt phase is `block`.

The future P4 implementation must inspect actual frozen source bytes with
parsers and HyperFrames checks. It must bind every planned lifecycle selector
and timeline call, require a non-opacity semantic Action, place Result after
Action, preserve the policy hold, and keep finite repeat tails inside the
shot/block window.

Hard failures include runtime network or CDN use, undeclared async,
`Math.random()`, `Date.now()`, unpaused or infinite timelines, irreversible
callbacks, duplicate/orphan/cross-block selectors, unregistered
token/type/component/motion references, terminal invisibility, source/shot
manifest drift, system/generic/local font fallback, CJK glyph-source gaps,
root escape, symlink input and hard-coded user paths.

Functional DOM text must carry a registered type role.
Every text element binds an element ID, selector, type role, semantic
responsibility and primary-meaning flag. `microtext-texture` cannot carry a
result or primary meaning. The functional result carrier selector appears in
both Result and Hold. Data labels, evaluated structured formula, unit,
denominator, source and evidence role must match the canonical shot plan.
Canonical source references cannot contain private local absolute paths.

The block receipt contains hashes, failure/warning codes, bounded metrics and
cache facts only. It contains no source text and no subjective quality result.
