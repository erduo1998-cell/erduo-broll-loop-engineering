# v0.8.0 Production Slim 实施计划

状态：发布执行记录
基线：公开 `v0.7.0`
完成终点：真实端到端测试通过，发布 `v0.8.0`，并将发布提交与 tag 成功推送到 GitHub。

## 1. 目标

`v0.8.0` 把 Skill 重新聚焦为“调教 AI 把视频做好的审美与编排能力”，删除日常生产中的重复环境审计和无效视觉检查。

必须同时做到：

1. 首次安装或升级时一次性完成环境排查，正常制片不再启动 Onboarding Agent。
2. 必须保留的工程与安全检查下沉到确定性脚本，Agent 只读取紧凑的 `pass / warning / fail` 结果。
3. 每条视频只执行与本次输入、所选后端和输出直接相关的轻量检查。
4. 删除 Builder、Integrator、Render 之间重复的条款、复核、安装和抽帧。
5. 用 `motion-layout` 代码筛查动态平滑度与运动中构图，异常时才生成取证；最终完整视频预览是唯一默认视觉/用户确认门。
6. 用同一条真实 SRT 对比 `v0.7.0` 与 `v0.8.0`，证明流程更轻且视频交付能力没有退化。

## 2. 非目标

- 不新增独立审美评分 Agent、逐镜审批、lookdev 阶段或新的人工停点。
- 不承诺代码能判断故事感染力或“高级感”；这部分由最终动态预览判断。
- 不重写 HyperFrames、Remotion 或 Shotcraft，不做无关架构升级。
- 不为了假想风险增加新安全条款；只保留真实执行边界。
- 不继续扩大静帧数量。静帧只用于异常定位，不作为动态质量证明。

## 3. 四类删减

| 归属 | 保留内容 | v0.8.0 行为 |
|---|---|---|
| 首次安装/升级 | Node、FFmpeg/FFprobe、Chrome、核心 Skills、HyperFrames/Remotion CLI 与版本 | 安装或升级时一次性检查并保存版本绑定结果；仅在版本变化、换机、文件失效或真实命令失败时重跑 |
| 确定性脚本 | 密钥清理、no-shell、no-overwrite、hash、schema、FFprobe、完整解码、依赖/身份核对 | 从 Prompt 和阶段重复条款中移除，统一输出紧凑机器结果；失败时只返回最短修复动作 |
| 每条视频轻检 | SRT 可读与时间闭合、所需后端可启动、输出目录可写与空间、目标不覆盖、实际需要时的媒体服务状态 | 单次快速 preflight，不派 Onboarding Agent，不准备未选择的后端 |
| 直接删除 | base/targeted 双 Onboarding、fresh repair 的全量重审、重复 `npm ci`/typecheck/still、阶段间重复安全合同、无异常的多轮抽帧 | 不迁移、不改名；从默认生产路径和 Agent 上下文中移除 |

运行期错误只做针对性修复。例如 Chrome 失败只修 Chrome，不重查 Node、FFmpeg、Skills 和另一套后端。

## 4. 视觉分析重构

### 默认路径

```text
代码与运行时轨迹 → motion-layout lint → 通过则继续
                                      → 异常则输出时间点、元素和诊断帧/短片
最终合成 → 一次完整动态预览 → 用户确认 → 正式渲染
```

### `motion-layout` 必查项

参考迪士尼动画 12 法则中可转成代码证据的部分，并检查：

- 进出场的速度、加速度、jerk 与端点缓入缓出，识别瞬移、突停和突然消失。
- 预备动作、跟随/重叠、回弹次数与幅度、动作是否完成沉降。
- 同一时刻启动的元素数量与独立运动中心，识别全屏一起动和动作主次丢失。
- 每个采样时刻的元素边界、遮挡、碰撞、安全区、文字可读停留和画面密度。
- 主视觉与次级元素的面积和层级，识别运动过程中逐渐堆叠、积压和构图失衡。
- 动画可 seek、确定性和时间轴闭合，禁止随机漂移或墙钟驱动。

筛查读取代码及运行时元素几何/透明度/层级/速度数据，输出紧凑 JSON。只有触发异常时才生成对应诊断帧或短片。静帧仍可用于证明字体丢失、越界或异常时间点，但不得重复覆盖 Builder、Integrator、Render 三个阶段。

### 唯一视觉门

- 默认只生成一次绑定最终 composition identity 的完整动态预览。
- 用户确认后，如项目身份和源码未变化，只核对 identity/hash 后正式渲染，不重跑整套安装、抽帧或视觉审核。
- 正式成片只做技术交付检查：规格、时长、音频策略、FFprobe 和完整解码。

## 5. 子任务分工

| 工作单元 | 责任 | 交付物 |
|---|---|---|
| 流程瘦身 | 重写父 Skill 与阶段编排，移除日常 Onboarding、重复 handoff 和重复视觉条款 | 精简生产状态机与阶段 Skills |
| 首次安装缓存/轻检 | 建立版本绑定环境 receipt、失效条件与单次 per-run preflight | 安装/升级检查、缓存读取、针对性修复 |
| 动画与构图筛查 | 实现跨后端 `motion-layout` 规则、紧凑报告和异常取证 | lint 脚本、fixtures、诊断输出契约 |
| 集成与发布 | 合并各单元，更新版本/README/变更记录，跑真实测试、打包、tag、push | `v0.8.0` 发布提交和远端 tag |

各工作单元可以由独立 subagent 并行执行；集成者必须复核真实源码、冲突、测试和最终结果，不能只接受 subagent 报告。

## 6. 测试矩阵

| 场景 | 必须证明 |
|---|---|
| 全新安装 | 一次完成 Node、FFmpeg、Chrome、Skills 与后端准备，receipt 可复用 |
| 正常第二次制片 | 不启动 Onboarding Agent，不重复安装，不检查未使用后端 |
| 升级或环境变化 | 只使相关缓存项失效；版本未变的项目不全量重审 |
| 单项故障 | Chrome/FFmpeg/后端任一失败时，只执行针对性诊断和修复 |
| HyperFrames 真实 SRT | 完成轻检、构建、lint、一次动态预览、渲染和完整解码 |
| Remotion 真实 SRT | 完成同等链路；不重复 `npm ci`、typecheck 或 still |
| 平滑度负例 | 瞬移、突停、线性硬进出、过度回弹、未沉降能被 lint 定位 |
| 构图负例 | 越界、碰撞、遮挡、元素积压、运动中心过多和可读停留不足能被定位 |
| 正常动画正例 | 合理的 stagger、ease、follow-through 和安全构图不产生大批误报 |
| 异常取证 | 只有失败项生成时间点、元素定位和最少诊断帧/短片 |
| 身份不变的批准后渲染 | 只做 identity/hash 与最终技术检查，不重跑视觉分析 |
| 回归与发布包 | `npm test`、Skill 校验、打包闭集、独立解包和公开 clone 可复现 |

真实测试至少使用一条冻结的 12–15 秒中文 SRT，在相同画幅、fps、字幕、音频政策与素材条件下完成 `v0.7.0`/`v0.8.0` 首次完整预览对照。

## 7. Token 与 I/O 验收指标

统计口径固定为相同输入下各 Agent 实际读取与产出的 Markdown/JSON 字节；宿主能提供 token 时同时记录 token。不得用文件总大小代替真实读取量。

- 整体 Agent 文本 I/O 相比 `v0.7.0` 减少至少 **60%**。
- Director + Builder 文本 I/O 减少至少 **50%**。
- 正常生产 Onboarding Agent 调用数为 **0**。
- 安装和环境安全长合同不进入 Builder/Integrator/Render 上下文。
- 默认静帧视觉检查从多阶段重复执行降为 **0 轮**；只有 lint 异常才按异常点取证。
- 最终完整动态预览为 **1 次**；批准后 identity 不变时不重新视觉分析。
- handoff 只传本阶段所需定位符、紧凑状态和异常摘要，不复制全片合同或全部 Recipe。

任一指标未达必须如实记录，不能用“功能完成”代替效率验收。

确定性 Prompt 代理可用
`npm run measure:context -- --baseline v0.7.0` 复跑，冻结结果见
`docs/V0.8.0-CONTEXT-MEASUREMENT.json`。该代理按各版本真实默认必读集
分别统计：v0.7.0 父级默认读取父 Skill 明列的 11 份 reference；v0.8.0
父级默认只读取自足的父 Skill，其余 reference 按决策加载。它不能代替
真实端到端宿主 token 与产物 I/O 记录。

## 8. 执行顺序与完成标准

1. 冻结 `v0.7.0` 对照输入、首轮预览和 I/O 基线。
2. 完成流程删减、首次安装缓存和单次轻检。
3. 实现 `motion-layout` 正负例与异常取证。
4. 集成 HyperFrames/Remotion 路线，删除旧的重复抽帧和重审入口。
5. 跑单测、回归、真实 SRT 端到端和 `v0.7.0`/`v0.8.0` 对照。
6. 只根据测试发现修复，直到全部发布阻断项通过。
7. 更新版本到 `0.8.0`、README、CHANGELOG、支持矩阵和发布检查表。
8. 生成并独立验证发布包，创建发布 commit 与 `v0.8.0` tag。
9. 推送目标分支/发布提交和 tag 到 GitHub，核对远端 commit、tag 与 CI。

只有同时满足以下条件才算目标完成：

- 两条后端中项目宣称支持的真实链路通过；未验证能力如实标记。
- 动态筛查正负例、异常取证、唯一最终预览和最终完整解码均通过。
- Token/I-O 指标达到本计划门槛，或由耳总明确接受实测差异。
- 工作树只包含本版本相关修改，无凭据、缓存、媒体产物和无关文件。
- GitHub 上的发布提交、`v0.8.0` tag、CI 和发布归档相互对应且可下载验证。
