# Delivery report contract

`delivery-report.mjs` converts verified delivery summary data into the only
user-facing completion report. It always reports the master, duration, actual
asset routes, authoring chunk count and validation, integrator no-rewrite,
pre-integration `style_conformance_review`, pre-render `source_code_review`,
technical verification and real limitations.
Per-shot directory/count are optional and appear only after the user explicitly
requested a master-derived export. It requires deterministic director facts,
`asset_fact_review`, the exact design-selection replay receipt and
visual-grammar/rules/font chain, every chunk's
seven passing gates, an approved current-byte `style_conformance_review` plus
independently revalidated integration authorization, a validated integration
manifest/no-rewrite receipt, `source_code_review` and final technical verify.
The delivery consumer is asynchronous and requires the same full evidence
bundle as final-render preflight: the actual style review and packet bytes,
artifact bytes, current block/chunk manifests and source bytes, operator-pinned
trusted capture runner, style integration authorization, integration manifest,
authoring plan and full source review. It reruns trusted capture/style,
authorization, no-rewrite integration and source-review validation, recomputes
the style-lineage render receipt internally, and only then cross-checks the
compact summary. A caller-provided or freshly re-signed lineage receipt is not
authority. The fixed style reviewer role/model/isolation/authority, subject
packet/current generation, style review, block/chunk sets, B↔C source ledger,
integration authorization, integration manifest/source bundle/no-rewrite
receipt and source review must all agree with the recomputed evidence. The
reported `validator_receipt_sha256` must be the same trusted-capture validator
receipt frozen inside the integration authorization and manifest.
`shot_plan_review`, `html_preview_review` and `final_frame_review` are legacy
inspection records and cannot satisfy the active topology. Child `approved`
receipts or `delivery_ready` flags are never enough to report delivery.

The summary rejects unknown fields, state/hash/error objects, credentials, source traversal paths, raw subtitles, unverifiable route names and unsupported compatibility claims. It may show the user-facing master and shots output locations; it never accepts source-media or internal cache/state locations. Known unverified facts use explicit wording: no Pexels Key test, Windows, and 剪映专业版桌面端.
