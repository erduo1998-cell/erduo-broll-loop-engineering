# B-roll assets producer

1. Require main `shot_plan_review` bound to the current plan manifest. Read only the artifact, asset-integrity, image-generation, Pexels-composition and font-asset contracts needed by the selected routes.
2. Route each planned primary material role in fixed order: relevant user media, real host image generation, then Pexels. Use specific native aid only for text, relationships, information graphics, motion or auxiliary structure. Never self-authorize native overage or jump directly from missing user media to Pexels while image generation is suitable and available.
3. Freeze every external file locally with checksum, probe, provenance and shot binding. Record a type-correct intended consumer. A video must bind to video/texture consumption; hidden declarations, `img src=mp4`, CSS `url(mp4)`, zero opacity and unbound sidecars are invalid.
4. For generated images freeze prompt hash, design/shot binding, target raster, probe result and suitability reason. For Pexels freeze subject, focal/crop/safe area, palette/depth/motion treatment, component/title relationship and later pixel-contribution region.
5. Freeze the complete inventory and composition records privately. Return the compact asset manifest envelope, stage receipt and a bounded path-free asset fact packet: candidate contact-sheet hash, selected keyframe hashes, selected route, rejection/fallback reasons and native-primary counts.
6. Run deterministic checksum, route, geometry and consumer validation. Do not approve inventory, build source or dispatch another stage. The parent directly issues `asset_fact_review` from the bounded packet. On rejection, accept one aggregate revision packet and return one replacement inventory.
