# Creative brief contract

## Owner and timing

The parent is the sole author of the brief and obtains explicit user confirmation before any producer child is created. It may make read-only SRT/media observations needed for the draft. A changed instruction creates a new brief hash and invalidates all downstream artifacts and reviews.

## Required decisions

Record each value as `user`, `observed fact`, or `parent proposal accepted by user`:

- content argument, audience, mode and desired response;
- aspect ratio, resolution, fps, duration/time source, audio, master and optional slice formats;
- user reference priority, one project-level visual direction, prohibited directions, primary/secondary DNA policy and motif intent;
- font roles, acquisition/licensing plan, required CJK coverage and prohibition on network/system fallback;
- material order, Pexels integration expectation and `native_route_max_bp` in `0…10000`;
- availability of a proven image-capable main agent that can inspect actual frames and video windows.

The brief never asks the user to install a director Skill. The bundled director method is always available. If the user explicitly provides a publicly licensed enhancer, record it as optional reference material, not a required capability.

Unknowns that materially change output block dispatch. Ordinary creative uncertainty becomes a bounded director decision.

## Artifact handoff

Freeze the full brief in private state. The parent retains only `{sha256, user_confirmation_sha256, native_route_max_bp, visual_review_required: true, font_asset_policy_sha256}`. Child packets receive that record and an artifact ID, not raw paths or unrelated user material. No stage receipt substitutes for confirmation.

## Prohibitions

- Do not dispatch preflight before exact confirmation.
- Do not accept an unexplained or unbounded native ceiling.
- Do not name a generic default font as the font strategy.
- Do not promise visual verification when the host cannot inspect actual rendered evidence.
