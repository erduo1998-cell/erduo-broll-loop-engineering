# Font asset contract

## Project-local fonts

Every visible font is a project asset. Supporting roles freeze `{font_id, role, family, weight, style, file_sha256, file_kind, official_source, license_id, license_file_sha256, commercial_scope, cjk_coverage_sha256}`. The bundled user display library is the authoritative byte source for the display role and must be represented in `assets/fonts/display-library.json`; its record is explicitly `{official_source: user-provided-display-library, source_status: user-provided}` rather than a fabricated license claim.

Use local `ttf`, `otf` or `woff2` files through explicit `@font-face`. Network imports, remote CSS, system stacks, generic browser fallbacks and silent substitution are invalid. Display, editorial/emotional, information and technical roles may use different families; a display face must not become the default body face.

Build a deterministic glyph set from all approved visible text. When a validated subsetter is callable, create and validate a deterministic subset. When no subsetter is callable, copy the already verified complete font file into the generated project; lack of a subsetter alone is not a blocker. Both paths must preserve the applicable license, bind the exact delivered bytes and checksum in the artifact manifest, cover every required glyph, load offline through local `@font-face`, and use no fallback. A missing verified full font remains a blocker.

For bundled display fonts, each run freezes one `display_selection` compatible with its primary visual DNA, then copies that exact catalogued local binary into the generated project and verifies its SHA-256. It must bind all `data-font-role` nodes for `key-quote`, `chapter-focus`, `core-number` and `emphasis` to that one local `@font-face`, with an auditable `data-display-font-id`; an absent, changed, unregistered, incompatible or mismatched display face is a hard failure. Information/technical faces remain independently configurable and must not silently become a display fallback. First acquisition of a non-bundled supporting face tries the pinned `raw_url`. Only a network or HTTP transport failure may fall back to GitHub Contents API → Git Blob API, using the same official repository, exact commit and exact `source_path`. Once either transport returns successfully, byte-length or SHA-256 mismatch is a hard failure and must not trigger the other transport, a mirror or any unpinned source.

## Gates

Preflight verifies that the planned roles can be satisfied with bundled or otherwise verified files and records whether subsetting is available. Source review verifies the one selected display font, its catalog evidence, complete-copy result, file hash, per-role DOM/CSS binding and absence of fallback; support faces retain their own license evidence. Render runs without network access and records `document.fonts.check` plus actual loaded family evidence. Visual review inspects target-language glyphs, density and readability in result frames. Any missing delivered bytes, catalog/license evidence where applicable, glyph coverage, loaded-family proof, role binding or visible glyph failure blocks delivery.
