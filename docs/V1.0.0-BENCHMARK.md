# v1.0.0 公开生产基准

本报告记录 v1.0.0 在一份约 180 秒真实 SRT 上的 Codex 端到端生产事实。它是单一样本，不代表所有输入、机器或宿主都能得到相同耗时和画面，也不构成审美批准或跨宿主等价证明。

## 结论

- 同一输入的 SRT SHA-256 为 `ff5b9fdc104318827804cf9b0be0e48febf1b81685fb5b509497f4e8996f73ea`，时长 `179.866` 秒，共 `124` 条 cue。
- Codex Agent cluster 生成 `20` 份 Shot Recipe v3，由 `1` 名 Lead Builder 和 `3` 名 production Builder 承担，三个 production unit 分别包含 `7 / 7 / 6` 个镜头。全程共 `10` 次 Agent 调用，full-history 调用为 `0`。
- 未使用外部素材。Director 在 visual-lock 技术见证中拒绝过一次，定点返修后复核通过；用户没有观看或作审美批准，因此最终 visual lock 状态是 `skipped`，不能写成 `approved`。
- 完整 preview 由 Director 独立抽检 `80` 帧，技术与语义检查通过；这不是用户审美判断。成片为静音，本次没有测试音画同步。
- 第一次完整 preview 从 Director 开始计约 `242.05` 分钟，未达到 `≤120` 分钟目标；Lead 阶段 `62.90` 分钟，未达到 `≤45` 分钟目标。目录和文件数目标通过，宿主 Token 指标未知。
- Claude Code 同输入对照尚未执行，保持 `pending`；不能把本次 Codex 结果外推到 Claude Code。

旧目录只做了独立只读扫描，没有重跑生产：

按相同的磁盘占用口径，v1.0.0 比旧 redo 减少约 `99.36%`；文件数也减少约 `99.36%`。不能用 v1.0.0 的逻辑文件大小 `158,806,133` bytes 与旧目录的 `du` 数值直接计算百分比。

旧 redo 的 `03-build` 子目录占用 `24,988,987,392` bytes，共 `32,881` 个文件、`5,176` 个 PNG、`10` 个视频；unit media 主要是 4K FFV1。其 preview 为 `179.866667` 秒、`1440 × 1080`、30 fps、静音 H.264，大小 `6,292,175` bytes。旧实施文档记录首次 preview 约 `334.45` 分钟，但本次没有独立复核这个时间。旧 Token 数字同样无法独立复核，因此不公开具体值。

## 限制

本次证据证明的是指定 Codex 样本的生产闭环、技术/语义抽检、输出身份和完整解码。它没有证明用户审美通过、音画同步、Claude Code 同输入表现、跨后端视觉一致性或其他输入的速度与质量。所有无法独立复核的 Token 与历史耗时都保持 unknown 或明确标注为文档记录。
