# v0.9.0 设计定稿

## 目标

在不压缩大模型创作空间的前提下，减少重复思考、重复安装、重复复制和无效检查；保留 SRT 全覆盖、总导演、素材负责人和多制作 Agent，并让口播分析产生的动画节拍真正出现在画面里。

## 六项收敛

### 1. 保留创作团队

- 保留 1 个总导演、1 个素材负责人和多个独立制作 Agent。
- 镜头按工作量分配给多个制作 Agent；例如 14 个镜头可分给 6 个制作 Agent。
- 返工交回原制作 Agent，不创建继承完整历史的新 Agent。

### 2. 把非创作工作改成脚本

- 软件环境检查、任务分配、文件与时间检查、镜头合并、预览和成片验证由脚本完成。
- 只有需要内容判断、视觉设计或素材选择的工作使用大模型。

### 3. 共用安装文件和素材

- 一条生产任务只保留一套安装文件和一份素材库。
- 每个制作 Agent 只保存自己负责的镜头源码和必要证明。
- 不复制完整工程、完整对话或无关镜头资料。

### 4. 调整总导演的设计顺序

- 先理解口播，再明确画面要帮助观众理解什么，最后自由创造构图、隐喻、动画和视觉风格。
- 风格不能代替内容表达，也不能让整片都依赖观众破解同一套抽象隐喻。
- 不采用“最少视觉机制”、优先复用旧解法、限制抽象比例、限制构图变化或要求复杂动画证明效率等创作限制。
- 保留丰富构图、多层动画、抽象隐喻、实拍与图形融合、相邻镜头变化和新视觉语言的创造空间。

### 5. 让动画节拍真正落到画面

- 总导演根据口播观点和情绪的推进安排动画节拍，不规定动画每几秒变化，也不套固定节拍数量。技术检测可以使用公开、经过测试的长段风险阈值，只发现未声明静止，不判断审美。
- 制作 Agent 必须实现每个节拍；主体、空间、大小、层级、材料、关系或视觉重点应出现可见发展。
- 装饰线条、粒子和背景循环不能冒充主要动画发展。
- 长镜头必须形成连续的发展过程，不能用一个基本不变的画面支撑十几秒或几十秒。
- 自动检查不仅验证“节拍写过且时间正确”，还验证实际画面在对应时间发生了计划中的明显变化。

### 6. 用户预览前自动闭环

- 合并后自动生成一次完整低清动态预览，检查内容对应、动画节奏、长时间无发展、文字可读性和整片一致性。
- 问题只回到原总导演或原制作 Agent 定点修正，不增加人工中间审核。
- 用户仍只看最终完整预览。

## 保留不变

- SRT 从零到最后一句连续覆盖。
- 按内容含义切镜，不按字幕条机械切镜。
- 多制作 Agent 并行，保证每个镜头获得足够注意力。
- 总导演建立整片统一世界，同时保持镜头变化。
- 动画节拍、动画原理、可编辑源码和双制作方式继续保留。
- 技术问题自动修正，用户只负责最终预览。

## 发布验收

- 正式版本号、Git 标签和 GitHub Release 使用 `v0.9.0`。
- README、CHANGELOG、安装文件、仓库内 Skill 和本机已安装 Skill 保持一致。
- 非创作步骤不再启动独立 Agent；制作 Agent 不继承完整历史。
- 同一任务不重复安装相同工具，不重复复制相同素材。
- 节拍检查能够拒绝“只写了节拍但画面没有明显发展”的示例。
- 仓库测试、Skill 校验、安装校验、发布包校验和公开仓库核验全部通过。

## 目标效果

- 14 镜头、约 3 分钟任务的 Agent 调用从约 20 次降至约 8 次基础创作调用。
- 首次完整预览目标由约 5 小时降至 60—90 分钟；实际时间仍受模型、素材下载和渲染机器影响。
- 大模型上下文消耗目标至少减半，争取降低约 70%。
- 生产目录不再出现多份相同安装文件，体积目标约 1 GB 上下。
- 长镜头随口播持续发展，不再以少量装饰线条运动冒充完整动画。
- 不降低创作上限；未来模型能力增强时，Skill 的创作质量可以继续提升。
